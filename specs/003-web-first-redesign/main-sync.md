## 4. Rulings (S13b, delegated by the owner)

1. Main's old-style UI files (`YearView.tsx`, the pill CSS) are not carried; the pure model files are.
2. Settings · Audio data's year lines are carried during the merge (trivial, on `StatusLine`), because without the done-line
   condition a years-only run would say "Nothing new to look up."
3. The README and inventory F20 describe the S13c design now (Released column, decade in Filters, Sort by year where the header
   cannot sort); T132 must build exactly what they describe (an acceptance item of T132), then rewrite F20's "What" column in
   the redesign's terms.
4. Create playlist's years on a failure before the playlist exists: saved with the tap's rows, `extras` and the stored check
   answers when nothing was saved during the run; a copy the owner saved during the run is kept whole and only gains the years,
   matched by track (fix round 1, M1, M2). The same by-track rule dates a copy saved during a successful run and the open rows.
5. A later worker result keeps an existing year when the new row has none.
6. Header word **Released**; **priority 2** on every table, Mix included (fix round 1, I2: four figures, a cheap width).
7. An undated song shows `NoData` (the dash announced "no data") in a table cell and nothing in a two-line meta line, departing
   from 005 FR-005's "nothing"; 005 SC-005 ("never 0 or a placeholder year") still holds.
8. The "Sort by year" switch is offered wherever header sort is unavailable or the Released column is hidden (two-line items,
   or a table under 720 px). This bends the "no header sort on phones" ruling only by adding a control in the Filters fold, so
   phones keep main's year sort.
9. Check on Spotify dates an undated row from the album of the track it found, like Create (fix round 1, I1); a dated row keeps
   its year.
10. By-track matching for years ignores the ISRC: an ISRC kept from a rejected identification never decides.
